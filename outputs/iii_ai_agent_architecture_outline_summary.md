## 一句話摘要

AI Agent 代表 AI 從「被動回答」轉向「自主完成工作」；企業導入重點不只在模型能力，而在模型、工具、協調層、基礎設施、互操作協定與 Agent Ops 治理能否形成穩定可控的工作系統。

## 核心重點

1. **開發典範從砌磚工轉向導演**  
   過去開發者必須明確寫出每一步邏輯；Agentic AI 時代，開發者設定目標、環境與工具，讓 Agent 自主規劃路徑、呼叫工具並應對例外。

2. **Agent 的四大核心不是只有模型**  
   完整 Agent 由模型、工具、協調層與部署基礎設施組成。模型負責推理，工具讓系統接觸外部世界，協調層管理記憶與行動迴圈，基礎設施提供安全、權限與擴展性。

3. **成熟度可用五級能力分類評估**  
   Level 0 是純推理系統，Level 1 開始使用工具，Level 2 能策略性拆解長任務，Level 3 進入多代理協作，Level 4 則具備自我演化能力。文章指出多數領先企業正從 Level 2 走向 Level 3。

4. **多代理協作是複雜任務的分水嶺**  
   單一 Agent 容易認知過載；多代理架構讓協調器、查詢分解、評論與報告 Agent 分工合作，提升準確度與可除錯性。

5. **互操作協定決定企業能否擴大部署**  
   MCP 像工具與資料的 USB 標準，A2A 支援 Agent 間能力宣告與協作，AP2 處理交易與支付授權。這些協定讓企業避免每個工具都重寫整合邏輯。

6. **Agent Ops 是落地成敗關鍵**  
   Agent 的輸出具有機率性，不能只靠傳統 DevOps 測試。企業需要 Evaluation、Traces 與 Feedback Loop，才能監控決策品質、追蹤思考過程並把錯誤回饋成測試資料。

7. **台灣企業應從流程而非聊天框出發**  
   適合優先導入的場景是重複性高、規則清楚、資料可治理的流程，例如採購核銷、初級客服與合規查詢。

## 簡報敘事線

簡報以「企業如何把 AI Agent 從概念導入可治理的工作系統」為主軸：

1. 先用軟體開發角色轉變說明為什麼 Agent 重要。
2. 拆解 Agent 架構，建立模型之外的全局觀。
3. 用五級成熟度協助企業定位當前能力。
4. 說明多代理、協定與 Agent Ops 如何支撐複雜任務。
5. 最後落到企業決策者的導入優先順序與治理清單。

### Slide 2：從砌磚工到導演

**重點**：
- Predictive AI：開發者微管理每一行邏輯。
- Agentic AI：開發者設定目標、環境、工具與護欄。
- 轉變核心是從邏輯編寫走向上下文工程。

### Slide 3：AI Agent 的企業價值

**重點**：
- 不只是回答問題，而是完成工作。
- Agent 能規劃、行動、觀察並修正。
- 企業價值來自流程重組與數位團隊化。

### Slide 4：四大核心架構

**重點**：
- 模型：推理、規劃、決策。
- 工具：搜尋、資料庫、API、程式執行。
- 協調層：記憶、步驟管理、推理-行動-觀察迴圈。
- 部署：安全、權限、擴展與監控。

### Slide 5：從 Level 0 到 Level 4

**重點**：
- Level 0：核心推理系統。
- Level 1：互聯的問題解決者。
- Level 2：策略性問題解決者。
- Level 3：協作式多代理系統。
- Level 4：自我演化代理。

### Slide 6：企業成熟度定位

**重點**：
- 多數領先企業正在從 Level 2 走向 Level 3。
- Level 2 適合流程自動化，Level 3 適合跨職能複雜任務。
- 成熟度提升會同步拉高治理與可觀測性需求。

### Slide 7：為什麼一個 Agent 不夠用

**重點**：
- 單一 Agent 會遇到認知過載。
- 多代理讓專案管理、查詢分解、審核與報告生成分工。
- 優點是準確度提高、除錯責任邊界更清楚。

### Slide 8：互操作三支柱

**重點**：
- MCP：模型連接資料與工具。
- A2A：Agent 之間交換能力與任務。
- AP2：讓 Agent 執行商業交易時具備支付授權與信任。

### Slide 9：Agent Ops

**重點**：
- 傳統 DevOps 假設輸入 A 應得到輸出 B；Agent 具有機率性。
- Evaluation 用模型協助評估答案品質與安全性。
- Traces 記錄推理與工具呼叫過程。
- Feedback Loop 把錯誤案例導回測試與改進。

### Slide 10：前瞻案例：AI 共同科學家

**重點**：
- 多代理協助文獻探索、科學辯論與假設生成。
- 價值是加速研究流程並提出人類可能忽略的新假設。
- 展現多代理在知識工作中的潛力。

### Slide 11：給台灣企業的行動建議

**重點**：
- 重新思考工作流程，不只導入聊天機器人。
- 先做資料治理，避免 Agent 無法取得正確資料。
- 建立人機協作治理、權限、護欄與審計。

### Slide 12：導入路線圖

**重點**：
- 選定高重複、規則清楚、資料可控的流程。
- 從 Level 2 單流程 Agent 做起。
- 加入 Agent Ops 後再擴展到 Level 3 多代理協作。
- 結論：競爭力來自能組建數位團隊的流程設計能力。

## 決策指南

### 優先導入順序

1. 盤點重複性高、錯誤成本可控、資料來源清楚的流程。
2. 建立資料品質、權限與 API 可用性清單。
3. 用 Level 2 Agent 試點單一流程，例如合規查詢、客服分流或採購核銷。
4. 導入 Evaluation、Traces、Feedback Loop，先確保可觀測與可治理。
5. 在任務複雜度提高後，再拆分角色形成 Level 3 多代理團隊。

### 導入前檢核問題

1. Agent 需要存取哪些資料？資料是否準確、結構化且有權限邊界？
2. 哪些工具或 API 允許 Agent 操作？哪些操作需要人工覆核？
3. 錯誤輸出會造成什麼損失？是否有護欄、回滾與審計紀錄？
4. 成功指標是效率、品質、成本、回應速度，還是新能力產出？
5. 是否已建立持續評估資料集與使用者回饋迴圈？
